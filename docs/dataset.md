# 土質パラメータ推定のためのデータ取得ガイド（OperaSim-AGX）

本書は、ブルドーザ（d37pxi_24）の作業データから土質パラメータを推定する推定器の学習用データセットを、OperaSim-AGX 上で作成する方法をまとめたものである。第1章で全体の仕組み、第2章で取得する特徴量の定義、第3章以降で作業手順と注意点を述べる。

---

## 1. 全体の仕組み

### 1.1 構成

```
episode_runner.py ──土質パラメータ・リセット指令──▶ SimEpisodeManager.cs（Unity）
        │                                                  │
        ├─ cmd_vel / blade_cmd で決まった動作をさせる        ├─ 地形リセット・土質変更
        │                                                  │
        └─ ros2 bag record でエピソードごとに記録 ◀── BladeStatePublisher.cs（反力・刃先位置など）
                    │                                       ＋ 既存の joint_states / global_pose
                    ▼
        bag_to_dataset.py → 時間軸を揃えた表（Parquet）＋ ラベル
```

| ファイル | 実行場所 | 役割 |
| --- | --- | --- |
| `BladeStatePublisher.cs` | Unity（d37pxi_24 に追加） | 排土板の反力の内訳、刃先位置、地面高さ、排土板角度を `/d37pxi_24/blade_state` に配信する |
| `SimEpisodeManager.cs` | Unity（Terrain に追加） | `/sim/episode_cmd` を受けて土質パラメータの設定と地形リセットを行い、現在の土質を `/sim/soil_params` に配信する |
| `episode_runner.py` | ROS2 側 | 土質パラメータと動作パターンの計画を作り、エピソードを自動で繰り返し実行・記録する |
| `bag_to_dataset.py` | ROS2 側 | 記録した rosbag を共通の時間軸に揃え、派生量を計算して Parquet に保存する |

### 1.2 1エピソードの流れ

1. 土質パラメータ（c, φ, ρ）を設定し、粒子を削除して地形の高さをリセットする。
2. 刃先前方の地面高さを測り、切削深さの基準 `ground_h0` とする。
3. rosbag の記録を開始する。
4. 停止したまま、排土板を初期の切削深さまで下げる。
5. 決められた深さ・速度のパターンに従って 10 m 前進する。
6. 停止して排土板を上げ、記録を止める。
7. 排土板を上げたまま後退し、スタート位置に戻る。

1エピソードはおよそ1分である。シミュレーションは実時間の約 0.7 倍で動くため、1時間あたり 50〜60 エピソードが目安となる。

### 1.3 データ収集の設計

**土質パラメータ：** c・φ・ρ の3つをラテン超方格法で範囲内に偏りなく配置する。それ以外の材料パラメータ（ヤング率、膨張率、締固め特性など）はプリセット dirt_1 の値で固定する。

| パラメータ | 仮の範囲 | 備考 |
| --- | --- | --- |
| 粘着力 c | 0〜20 kPa | 乾いた砂〜やや粘性のある土を想定 |
| 内部摩擦角 φ | 25〜45° | |
| 密度 ρ | 1300〜1900 kg/m³ | Maximum Density（2000）を超えないこと |

範囲は仮のものであり、松島先生と相談して確定させる。

**動作パターン：** 切削深さへの依存性の違い（重さの項は d²、粘着力の項は d に比例）を利用して c と ρ を分離できるよう、深さを変える走り方を含める。

| パターン | 内容 | 狙い |
| --- | --- | --- |
| `const` | 一定の深さで直進 | 基本条件 |
| `step` | 深さを段階的に切り替える | 深さへの依存性を分離する |
| `sine` | 深さを正弦波状に変化させる（波長 2〜5 m） | 同上。連続的な変化 |

初期深さは 3〜12 cm、変化の振幅は 1〜4 cm、前進速度は 0.3〜1.0 m/s の範囲でランダムに決める。

## 2. 取得する特徴量

### 2.1 特徴量の分類

特徴量は役割によって次の5種類に分ける。

| 分類 | 役割 | 例 |
| --- | --- | --- |
| ラベル | 推定の正解。エピソード内で一定 | c, φ, ρ |
| 主入力 | 推定器に入れる中心的な観測量 | 排土板の反力、切削深さ、排土板角度 |
| 補助入力 | 推定の精度を上げる、または状況を区別するための観測量 | 車速、車体姿勢、前方土量 |
| 実機相当入力 | 実機でも計測できる量。第2段階で主入力と置き換える | 関節・履帯の effort |
| 記録用 | 解析・デバッグ・制御の再現に使う | 指令値、位置 |

### 2.2 座標系と時刻の約束

- **力の座標系：** 車体（base_link）に固定した座標系で表す。軸の向きは ROS の慣例（FLU）に従い、**x が前方、y が左方、z が上方**である。車体が傾いていても、常に車体から見た向きで表される。
- **位置・高さの座標系：** ワールド座標で表す。`blade_state` の位置は Unity 座標を ROS の向きに並べ替えたもの（x = Unity の z、y = −Unity の x、z = Unity の y）であり、高さ（z）は Unity のワールド y 座標と同じ値である。`global_pose` のワールド座標系と一致するかは、`global_pose` の `frame_id` と実際の値で確認すること。
- **時刻：** すべてシミュレーション時刻（秒）で扱う。変換後のデータの `t` は、エピソードの記録開始を 0 とした経過時間である。
- **サンプリング：** AGX の更新周期は 50 Hz（1ステップ 20 ms）であり、`blade_state` も 50 Hz で配信する。変換時に全データを 50 Hz の共通時間軸に線形補間で揃える。

### 2.3 ラベル（土質パラメータ）

`/sim/soil_params` から取得する。この値は、Unity の材料アセットではなく AGX 本体の地形材料から読み戻した値なので、設定が実際に反映されたことの確認にもなる。

| 列名 | 単位 | 定義と物理的な意味 |
| --- | --- | --- |
| `label_c` | Pa | **粘着力。** 土粒子同士がくっつく強さ。粘土で大きく、乾いた砂ではほぼ 0。FEE では切削深さ d に比例する抵抗の項を決める。履帯の最大牽引力 H_max = A c + W tan φ にも効く |
| `label_phi` | deg | **内部摩擦角。** 土粒子同士の摩擦の強さ。砂で大きく、粘土で小さい。FEE では N 係数を通じて非線形に抵抗を変える。牽引力にも効く |
| `label_rho` | kg/m³ | **密度（地山の密度）。** 単位体積重量は γ = ρ g。FEE では d² に比例する重さの項を決め、押した土の体積と重さの換算にも使う |

注意：推定器が推定するのは、排土板前方のくさび形の土塊と直近の時間窓で平均した「実効的な」土質パラメータである。本データセットでは地盤が均一なので、実効値と設定値は一致するとみなしてよい。

### 2.4 主入力：排土板の反力

`/d37pxi_24/blade_state` から取得する。AGX の地形モジュールが計算した、排土板（Shovel）と土の間の力であり、重力やノイズを含まない「真値」である。AGXUnity の `DeformableTerrain.ShowForces()` と同じ API・同じ符号の扱いで取得している。

| 列名 | 単位 | 定義と物理的な意味 |
| --- | --- | --- |
| `F_total_x` | N | **合力の前後成分。** 下の4つの力の和。土を押して前進しているとき、走行を妨げる向き（負）になる想定。FEE の水平方向の力 P sin(α+δ) と押土の摩擦抵抗の和に対応する。推定で最も重要な量 |
| `F_total_y` | N | **合力の左右成分。** まっすぐ前進している限り小さい。排土板に角度を付けたときや旋回時に現れる |
| `F_total_z` | N | **合力の上下成分。** FEE の鉛直方向の力 P cos(α+δ) に対応する。前後成分との比が、排土板角度 α と土–排土板間の摩擦角 δ に関係する |
| `F_pen_x/y/z` | N | **貫入抵抗。** 刃先がまだ削られていない地面に食い込むときの抵抗。切削している区間で現れる |
| `F_sep_x/y/z` | N | **Separation force。** 地形から切り離され、排土板の前に溜まった土塊からの力。押土している区間で支配的になる。実験では前進時にほぼすべてがこの力だった |
| `F_def_x/y/z` | N | **Deformation force。** 排土板が切削方向以外（後ろ・横）に土を押しのけるときの力。まっすぐ前進している限り 0 |
| `F_con_x/y/z` | N | **Contact force。** 排土板の面が、まだ削られていない地面に直接押し付けられたときの力。通常の前進では 0 |

**使い方：** 推定器の入力には基本的に合力（`F_total_x`, `F_total_z`）を使う。内訳は、切削している区間（貫入抵抗が大きい）と押土だけの区間（Separation だけ）を区別し、FEE の切削の項と押土の項を分けて検証するための解析用に残す。

**注意：** 排土板の前でこぼれた土の粒子と排土板の接触は通常の剛体接触として扱われるため、この4つの力には含まれていない可能性がある。後で関節の拘束力から求めた合力と比較し、取りこぼしの大きさを確認することが望ましい。

### 2.5 主入力：排土板と切削の状態

#### `blade_state` から取得するもの

| 列名 | 単位 | 定義と物理的な意味 |
| --- | --- | --- |
| `edge_x`, `edge_y`, `edge_z` | m | **刃先中点のワールド位置。** Shovel の Cutting Edge の両端の中点。`edge_z` が刃先の高さで、切削深さの計算に使う |
| `ground_below` | m | **刃先の真下の地面高さ（ワールド）。** 削った後の地形の高さなので、切削中はほぼ刃先の高さと一致する。刃先が地面より上にあるか（空振りしていないか）の判定に使う |
| `ground_ahead` | m | **刃先から 0.5 m 前方の地面高さ（ワールド）。** まだ削っていない地面の高さ。エピソード開始時の値を切削深さの基準 `ground_h0` として使う。ただし、前方に土の山がある場合、山が地形の高さとして扱われているかどうかで値が変わるので注意 |
| `blade_alpha_deg` | deg | **排土板の角度 α。** 刃先中点から上端中点へ向かうベクトルが、水平（車体の後ろ向き）となす角。FEE の α と同じ定義で、90° で排土板が垂直、90° より小さいと上端が後ろに倒れている。チルト操作や車体のピッチで変化する |
| `front_soil_mass` | kg | **排土板前方の土の質量。** FEE の上載荷重 q に関係する。取得する API が未確認のため、現時点では NaN |

#### 変換時に計算するもの（派生量）

| 列名 | 単位 | 定義と物理的な意味 |
| --- | --- | --- |
| `depth` | m | **切削深さ d。** `ground_h0 − edge_z`。正のとき刃先が元の地面より下にある。FEE の中心的な入力で、重さの項は d²、粘着力の項は d に比例する。平らな地面での実験を前提とした定義 |
| `cut_volume` | m³ | **累積切削体積（地山の体積）。** 排土板幅 × max(d, 0) × 進んだ距離 を時間積分したもの。こぼれを無視すれば、排土板の前に溜まった土の体積に相当し、ρ を掛けると質量になる。実機でも計算できる量なので、`front_soil_mass` が取れない場合の前方土量 q の代わりとして使う |

**注意：** `cut_volume` の計算には排土板幅（刃先の長さ）が必要である。`bag_to_dataset.py` の `--blade-width` に、Shovel の Cutting Edge の両端の距離を指定すること。

### 2.6 補助入力：車体の状態

`/d37pxi_24/global_pose`（`nav_msgs/Odometry`）から取得する。

| 列名 | 単位 | 定義と物理的な意味 |
| --- | --- | --- |
| `x`, `y`, `z` | m | **車体のワールド位置。** 走行距離の計算と、エピソードの開始・終了位置の確認に使う |
| `roll`, `pitch`, `yaw` | rad | **車体の姿勢。** `pitch` は前後の傾きで、排土板にかかる負荷が大きいと前のめりになる、刃先の高さがずれる、といった影響を判断するのに使う。`yaw` は直進できているかの確認に使う |
| `vx`, `vy`, `vz` | m/s | **車体の速度。** `child_frame_id` の座標系で表される（車体座標の場合、`vx` が前進速度）。どの座標系かは実データで確認する |
| `wz` | rad/s | **旋回角速度。** 直進中はほぼ 0 |
| `speed` | m/s | **（派生）水平面内の速さ。** `vx` と `vy` から計算する。指令速度との差は、履帯のスリップ（土が重い・硬いほど大きい）を反映する |
| `distance` | m | **（派生）走行距離。** `speed` の時間積分。土質や深さのパターンを、時間ではなく位置に対して見るときに使う |

### 2.7 実機相当入力：関節と履帯の状態

`/d37pxi_24/joint_states` から取得する。各関節について位置（`_pos`）、速度（`_vel`）、力（`_effort`）の3つの列ができる。

| 関節名 | 意味 | 推定での使い道 |
| --- | --- | --- |
| `lift_joint` | 排土板の上げ下げ | effort は排土板を支える力で、反力の上下成分を強く反映する。ただし排土板と腕の重さを含み、振動的なノイズも大きい。実機のリフトシリンダ圧に相当する |
| `tilt_joint` | 排土板のチルト（前後の傾き） | 位置は排土板角度 α に関係する。effort は小さい |
| `angle_joint` | 排土板のアングル（左右の振り） | 本データセットでは固定。effort は角度を保持する力でほぼ一定 |
| `right_track` | 右履帯 | effort は駆動力（トルク）で、反力の前後成分と走行抵抗の和を反映する。実機の走行モータのトルクに相当する |
| `left_track` | 左履帯 | 同上 |

**単位について：** 各関節が回転関節か直動関節かによって、位置は rad か m、effort は N·m か N になる。Unity 側のモデル（AGXUnity の Hinge か Prismatic か）を確認し、本書に追記すること。

**使い方：** 第1段階では主入力（真値の反力）で推定器を作る。第2段階で、入力を `lift_joint_effort` と左右の履帯の effort に置き換えても推定できるかを検証する。その準備として、次の2つの基準値を別途記録しておく。

- 排土板を空中に上げて静止したときの effort（排土板の重さの分）
- 排土板を上げたまま平地を走ったときの effort（走行抵抗の分）

土の反力は、この基準値からの差として現れる。

### 2.8 記録用：指令値

| 列名 | 単位 | 取得元 | 意味 |
| --- | --- | --- | --- |
| `cmd_vx` | m/s | `/d37pxi_24/cmd_vel` | 前進速度の指令。実際の速度との差がスリップを表す |
| （変換対象外） | — | `/d37pxi_24/blade_cmd` | 排土板の指令。rosbag には記録されるが、独自型（`com3_msgs/JointCmd`）のため変換では扱っていない |

### 2.9 推定器に使う特徴量の組み合わせ（案）

| 組み合わせ | 特徴量 | 用途 |
| --- | --- | --- |
| 最小構成 | `F_total_x`, `F_total_z`, `depth`, `blade_alpha_deg`, `speed`, `cut_volume` | FEE と同じ情報。まずこれで推定できるかを確かめる |
| 標準構成 | 最小構成 ＋ `pitch`, `cmd_vx`, `lift_joint_pos` | 車体の状態による影響を推定器に考慮させる |
| 実機相当構成 | 最小構成の `F_total_x`, `F_total_z` を `lift_joint_effort`, `right_track_effort`, `left_track_effort` に置き換える | 実機に近い条件での検証（第2段階） |

## 4. 作業手順

### ステップ1：Unity 側の動作確認

Play したうえで、配信内容を確認する。

```
ros2 topic echo /d37pxi_24/blade_state
ros2 topic echo /sim/soil_params
```

確認すること：

- 力の大きさが、確認用ウィンドウ（Shovel forces）の合力と一致する（座標の並びは違ってよいので、各成分の2乗和の平方根で比べる）。
- 土を押して前進しているとき、`F_total_x`（data の1番目）が負になる。
- 刃先高さ（data の18番目）が、排土板の上げ下げに合わせて変わる。

土質の変更と地形のリセットは、手動で指令を送って確認する。

```
ros2 topic pub --once /sim/episode_cmd std_msgs/msg/Float64MultiArray "{data: [1, 10000, 30, 1600, 0]}"
```

`/sim/soil_params` の値が 10000・30・1600 に変わり、地形が元に戻れば成功である。

### ステップ2：排土板の向きの較正

`lift_joint` に正の速度を送ったとき排土板が上がるか下がるかを確認する。

```
python3 episode_runner.py --calibrate
```

表示された `--lift-sign` の値を、以降の実行で必ず指定する。

### ステップ3：試験的な収集（5エピソード程度）

```
python3 episode_runner.py --num-episodes 5 --lift-sign <較正結果> --out ~/dataset/pilot
```

最初の数エピソードは画面を見ながら次を確認する。

- 排土板が指定した深さに追従しているか。追従が遅い・振動する場合は `--kp`（比例ゲイン）と `--lift-vmax`（最大速度）を調整する。
- 10 m 走ったところで止まるか。
- 後退してスタート位置に戻れるか。

主なオプションは次のとおりである。

| オプション | 既定値 | 意味 |
| --- | --- | --- |
| `--num-episodes` | 5 | エピソード数 |
| `--seed` | 0 | 計画の乱数シード。同じ値なら同じ計画になる |
| `--c-range` | 0 20000 | 粘着力の範囲 [Pa] |
| `--phi-range` | 25 45 | 内部摩擦角の範囲 [deg] |

| `--lift-sign` | 1 | 排土板の上げ下げの向き（較正結果） |
| `--kp`, `--lift-vmax` | 1.0, 0.1 | 刃先高さの追従制御のゲインと最大速度 |

### ステップ5：再現性の確認

同じ土質・同じ動作で3回走らせ、合力のばらつきを確認する（`--seed` を固定して `--num-episodes 1` を3回実行すればよい）。土質の違いによる合力の差が、このばらつきより十分大きければ、本番の収集に進む。

### ステップ6：本番の収集

数百エピソードを夜間などにまとめて実行する。目安として、500 エピソードでおよそ10時間かかる。学習用・検証用・テスト用に分けるため、テスト用には学習範囲の外側の土質を含めた別の実行（別の `--seed` と範囲）も用意しておく。

## 5. 出力データの構成

```
~/dataset/<実行名>/
  ├ episodes.csv            エピソードの計画と結果（土質、動作パターン、ground_h0、成否）
  ├ ep0000/                 rosbag（エピソードごと）

  │  …

      ├ episodes.csv        変換に成功したエピソードの一覧
      ├ ep0000.parquet      1行 = 1時刻（50 Hz）。第2章の列を含む
      └ …
```

`episodes.csv` の列は次のとおりである。

| 列名 | 意味 |
| --- | --- |
| `id` | エピソード番号 |
| `c`, `phi`, `rho` | 設定した土質パラメータ（ラベル） |

| `status` | `ok` または失敗時のエラー内容 |

## 6. 注意点と既知の課題

- **未検証のコードである。** 4本のスクリプトはいずれも実環境での動作確認前であり、Unity 側は AGX の API 名、ROS2 側はトピックの挙動に依存する部分がある。
- **`ros2 bag record --use-sim-time`：** 使用している ROS2 のバージョンにこのオプションがない場合は外す。その場合、ヘッダを持たない `cmd_vel` の時刻だけが実時間になるため、変換スクリプトの扱いを変える必要がある。
- **前方土量：** `front_soil_mass` は API 確認まで NaN である。当面は `cut_volume` を代わりに使う。
- **履帯のスリップ率：** 起動輪の半径が不明なため未計算である。Unity のモデルで半径を確認できたら、`1 − 車速 ÷（履帯の回転速度 × 半径）` として派生量に追加する。
- **粒子からの力：** 2.4 節の注意のとおり、排土板の前でこぼれた粒子からの力は反力に含まれていない可能性がある。
- **inverse crime：** AGX の掘削抵抗の計算が FEE に由来するモデルであれば、推定器側も FEE を使うと推定が実際より簡単に見える。評価の段階では、推定器側のモデルを意図的に簡略化する、観測にノイズを加えるなどの工夫が必要になる。
